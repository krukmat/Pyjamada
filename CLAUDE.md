# CLAUDE.md

## Project

Pyjamada is an Android-first React Native/TypeScript game experiment. The active product has a single gameplay path: the systemic bedroom run. The old Classic V1 three-room slice was intentionally removed; Git history is the archive.

Current baseline: **v0.9.0**.

## Commands

```bash
npm install
npm start
npm run android
npm run test:all
npm run typecheck
npm run screenshots:android
```

## Architecture

```text
React Native shell
  App.tsx
  ├── MainMenu
  ├── SettingsScreen
  └── GameScreen
       └── GameCanvas (Skia)

Pure TypeScript gameplay
  src/game/systemic/
  ├── SystemicState
  ├── SystemicContent
  ├── SystemicRuleEngine
  ├── SystemicRuntime
  ├── SystemicCodec
  └── SystemicTelemetry

Persistence
  GameSavePort
  AsyncStorageGameSaveRepository
  key: pyjamada:game:v1:run

Settings remain a separate persistence domain.
```

`systemic` is an architectural/domain term. It no longer denotes an experimental alternative mode.

## Invariants

- Gameplay updates are deterministic and live in pure TypeScript.
- React and Skia render state; they do not implement game rules.
- The active room has six objects: bed, alarm clock, wardrobe, slippers, window and keys.
- The rule engine has ten ordered reusable rules.
- Objective completion requires dressed + keys.
- Failure conditions are excessive noise, exhaustion or exceeding the time deadline.
- Save payloads are versioned and validated before use.
- Settings and game save use separate storage domains.
- Presentation may evolve without adding hidden gameplay state.
- Do not reintroduce a Classic/Systemic product split. Experimental work should evolve the single active game path.
- Do not use protected/original Pyjamarama assets.

## Validation

`npm run test:all` covers gameplay/codec/telemetry and settings. `npm run typecheck` covers the RN/Skia shell. Android visual evidence is generated by the single `npm run screenshots:android` tour.

See `docs/GAMEPLAY.md` and `docs/ANDROID_SMOKE_TEST.md`.
